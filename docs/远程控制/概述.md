# 远程控制（dsh-my-remote）

> 模块文档：`docs/远程控制/` — 源码：`plugins/dsh-my-remote/`

**dsh-my-remote** 是 DSH 远程控制插件（issue #75）：离开电脑后，`ask`（agent 提问）、`approval`（等待批准）、`end`（会话结束）事件实时**下行**到外部通道（手机 / IM / 中转服务），外部经受鉴权的入站 API 可以**回答 ask**、**批准 approval**、**查询会话状态**、**继续任务**——会话不再因无人操作而挂起。

## 业务场景映射

| 业务关键词                     | 入口                                                          | 说明                                                                                            |
| ------------------------------ | ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 事件下行 / 出站事件 / ask 下发 | `plugins/dsh-my-remote/lib/events.js` `tools/execute` 监听    | 命中 `ask_user_question` 时推送 `kind: ask` 帧（含问题 id/文本/可选选项），同时注册等待远程回答 |
| 事件下行 / approval 下发       | `plugins/dsh-my-remote/lib/events.js` `approval/request` 监听 | 推送 `kind: approval` 帧（原因 + 工具名），同时注册等待远程决议                                 |
| 事件下行 / 会话结束            | `plugins/dsh-my-remote/lib/events.js` `agent/status` 监听     | `idle` 时推送 `kind: end` 帧并清理该会话未决 ask/approval（fail-closed）                        |
| 远程回答 ask / answer          | `plugins/dsh-my-remote/lib/commands.js` `answer` 指令         | 按 sessionId 决议注册表，事件层短路返回 `{ value: { answers } }` 注入 agent                     |
| 远程批准 approval / approve    | `plugins/dsh-my-remote/lib/commands.js` `approve` 指令        | 决议 `allowed-once`（批准）/ `rejected`（拒绝），事件层返回 outcome                             |
| 继续会话 / continue / steer    | `plugins/dsh-my-remote/lib/commands.js` `continue` 指令       | `agent.steer(userMessage(text))` 注入用户消息，唤醒/继续会话                                    |
| 状态查询 / status              | `plugins/dsh-my-remote/lib/commands.js` `statusSnapshot`      | 活动顶层会话 + 待回答 ask + 待批准 approval 快照                                                |
| 操作审计 / audit               | `plugins/dsh-my-remote/lib/audit.js`                          | 所有指令与失败（含 token 失败、未知动作）留痕，内存环形缓冲 100 条                              |
| 通道 / 适配器 / webhook        | `plugins/dsh-my-remote/lib/channels.js`                       | 出站事件 POST 到配置 webhook（重试 + 超时 + 失败记录）；IM 适配器按同一契约扩展                 |

## 架构（分层，与 issue #75 建议一致）

```
┌──────────────┐   事件下行(出站 webhook)    ┌──────────────┐
│ DSH 插件      │ ──────────────────────────→ │ 外部通道      │ ←→ 手机 / 微信 / QQ / 飞书
│ dsh-my-remote │ ←────────────────────────── │ (中转服务/机器人) │
└──────────────┘   指令上行(入站 API + token)  └──────────────┘
```

1. **事件层**（`lib/events.js`）：监听 `agent/status`（end）、`tools/execute`（ask）、`approval/request`（approval）。ask/approval 拦截用 **`Promise.race([next(), 远程决议])`**：
   - 本机先操作 → `next()` 透传，体验与不装插件一致；
   - 远程先到达 → 短路返回注入结果（ask 返回 `{ value: { answers } }`，approval 返回 `'allowed-once'`/`'rejected'`）；
   - 可配超时（ask 超时返回空 answers 由模型自行决策；approval 超时 fail-closed 拒绝）；
   - 会话结束（idle）时未决条目按 fail-closed 清理（approval → rejected，ask → deny 语义），防会话结束后远程指令绕行。
2. **指令层**（`lib/commands.js`）：入站指令**白名单**（answer / approve / continue）+ 状态快照 + 全部写指令审计。
3. **渠道层**（`lib/channels.js`）：事件帧与指令格式**渠道无关**；HTTP 适配器先行（POST 结构化事件帧到中转服务）；微信/QQ/飞书机器人按适配器契约扩展。
4. **安全层**：loopback 信任围栏（dsh-shared `isTrustedApiRequest`，与 /api 网关一致）+ `apiToken`（写指令 `x-remote-token` 头）+ 指令白名单 + 操作审计。

模块文件：`lib/index.js`（组装）、`lib/registries.js`（ask/approval 待决议注册表）、`lib/session.js`（会话 helper：顶层判定/标题/问题结构化）、`lib/audit.js`（审计缓冲）、`lib/routes.js`（/remote/api 路由）。

## HTTP API（/remote/api）

所有请求先过 loopback 围栏；`POST /remote/api/command` 写指令在配置 `apiToken` 后要求 `x-remote-token` 头。

| 端点                  | 方法 | 说明                                                           |
| --------------------- | ---- | -------------------------------------------------------------- |
| `/remote/api/info`    | GET  | 插件开关与 apiToken 是否启用（不暴露值）                       |
| `/remote/api/status`  | GET  | 活动会话 / 待回答 ask / 待批准 approval 快照                   |
| `/remote/api/audit`   | GET  | 操作审计日志（命令/来源/时间/结果）                            |
| `/remote/api/command` | POST | 远程指令统一入口：`{ action, ... }`（answer/approve/continue） |

command 动作示例：

```jsonc
// 回答 ask（按问题 id 选择选项 / 自由文本 custom）
{ "action": "answer", "sessionId": "s1", "answers": [{ "id": "q1", "selected": ["继续"] }] }
{ "action": "answer", "sessionId": "s1", "answers": [{ "id": "q1", "selected": [], "custom": "换一个方案" }] }
// 批准 / 拒绝 approval
{ "action": "approve", "sessionId": "s1", "outcome": "allowed-once" }
{ "action": "approve", "sessionId": "s1", "outcome": "rejected" }
// 继续 / 唤醒会话
{ "action": "continue", "sessionId": "s1", "message": "继续下一步" }
```

下行事件帧（POST 到配置的 webhook URL，JSON）：

```jsonc
{ "kind": "ask", "sessionId": "s1", "title": "会话标题",
  "questions": [{ "id": "q1", "header": "", "question": "是否继续部署?", "options": ["继续", "取消"] }],
  "time": 1788520000000 }
{ "kind": "approval", "sessionId": "s2", "title": "会话标题", "reason": "需要执行 bash", "toolName": "bash", "time": ... }
{ "kind": "end", "sessionId": "s1", "title": "会话标题", "time": ... }
```

## 通道适配器扩展（微信 / QQ / 飞书机器人）

**契约**：渠道无关的事件帧（上表）与指令格式（command 动作）已固定；新增 IM 渠道只需实现适配器：

```js
// 适配器契约（示意）：把事件帧转为 IM 消息卡片，把 IM 消息/按钮回调转为指令
{
  id: 'wecom',                       // 渠道名
  async sendEvent(event) {},          // event = 下行帧（kind/sessionId/…）→ IM 消息
  async handleCallback(body) {},      // IM 回调 → 复用 processCommand（answer/approve/…）
}
```

- **微信**（企业微信机器人）：`sendEvent` 把 ask 帧渲染为文本卡片（`【需要你回答】…（会话 s1）`）+ 按钮；`handleCallback` 把按钮回调映射为 `{ action: 'answer' | 'approve', sessionId, … }` 交指令层。
- **QQ / 飞书**：同理，仅协议转换（消息格式/回调签名）不同。
- 事件层/指令层/安全层**零改动**——适配器只做「事件帧 ↔ 渠道协议」与「渠道回调 ↔ 指令」双向转换。
- 现有 HTTP 通道即「通用中转」：外部服务端接收事件帧，负责把帧转发给手机 App / IM，并把用户的回答/批准回传 `/remote/api/command`。

## 安全模型（远程控制比通知更敏感）

| 层          | 机制                                                                                                                               |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 来源        | loopback 围栏：非本机请求需配置 `trustedHosts`（webRuntime），`sec-fetch-site`/origin 同源校验                                     |
| 鉴权        | `apiToken` 配置后写指令必须携带 `x-remote-token` 头（值绝对不暴露给 info 接口）                                                    |
| 白名单      | 指令动作白名单（answer/approve/continue），未知动作 400 + 审计                                                                     |
| 审计        | 所有指令（含 token 失败、未知动作尝试）记录：时间/来源/动作/sessionId/结果/详情；内存环形缓冲 100 条，`GET /remote/api/audit` 可查 |
| fail-closed | 会话结束/超时未决 approval → rejected；非法 outcome 注入 → rejected；answers 参数非法 → 400                                        |
| 单次消费    | 注册表决议后条目删除：同一 sessionId 的第二次 answer/approve 返回 not-found（防重放）                                              |

## 与其它插件的关系

- **dsh-my-notify**：负责浏览器通知 + SSE + 出站 IM 机器人 webhook（企微/飞书/钉钉格式化与签名）；本插件定位**远程控制**（上行回答/批准 + 状态 + 继续 + 审计），下行事件走通用中转（结构化帧），不重复 IM 格式化——如需通知 + 远程控制兼备，两者可同时启用，事件推送各自按配置工作。
- **dsh-task-reliability**：其 trigger 接口可回答「自主决策模式拦截后的离线问题」，但非实时 ask；本插件拦截**正在进行的 ask/approval** 实现实时回答/批准；`agent.steer` 注入模式同源。
- **dsh-shared**：复用 `isTrustedApiRequest` / `readJsonBody` / `writeJson` / `writeError` / `header` / `userMessage`。

## 资源影响

- 纯内存：注册表（pending ask/approval 条目数）、审计（≤100 条）、失败记录（≤50 条）；无持久化、无轮询、无定时器（除可配超时与推送退避的一次性 sleep）。
- 事件驱动：只在 ask/approval/end 发生时工作，空闲零开销。
- 写放大：零（无磁盘写入）。
