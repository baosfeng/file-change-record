# dsh-skill-manager 需求清单

> ⚠️ **每次开发本插件的新功能或修复前，必须逐条对照本清单**：新改动不得破坏任何一条既有需求。

## 1. 核心需求

| # | 需求 | 现状 | 验证方式 |
|---|------|------|---------|
| R1 | **Skill 列表（分「全局 / 项目」两维度）**：每个 skill 显示名称、描述、来源（全局：`user-dsh`/`user-agents`/`custom`/`bundled`；项目：`project-dsh`/`project-agents`）、状态（启用/已禁用） | client `SkillManagerView` 两区块渲染 + `GET /skill-manager/api/list` 合并目录与配置 | `test/client-render.mjs`、`test/host-api.mjs` |
| R2 | **按项目启用/禁用**：项目配置 `<项目根>/.dsh/skills.enabled.json`（随仓库版本化）；全局配置 `$DSH_HOME/skills.enabled.json`；全局与项目分开管理 | `config.js` 双作用域读写 + `PUT /skill-manager/api/config` | `test/host-provider.mjs`、`test/host-api.mjs` |
| R3 | **禁用即不注入**：禁用的 skill 不再注入该项目会话——模型不可见、不可加载 | rank-0 占位 provider 覆盖合并目录；`get()` 返回 `undefined` 拒绝加载正文 | `test/host-provider.mjs`（rank/description/provider 断言） |
| R4 | **项目覆盖全局**：全局 skill 也可在项目内单独禁用 | `disabledNamesOf(cwd)` 合并 `global.disabled ∪ project.disabled` | `test/host-provider.mjs` |
| R5 | **即时生效**：保存配置后 skill 目录缓存失效重算，无需重启 | API 保存后调用 `control.invalidate()` | `test/host-api.mjs`（invalidate 计数） |
| R6 | **配置容错**：配置文件缺失/损坏降级为空配置，不崩溃 | `readConfigFile` try/catch + `normalizeConfig` | `test/host-provider.mjs` |
| R7 | **API 安全**：`/skill-manager/api/*` 只接受回环/可信 host，拒绝跨站 | `fence.js`（同 /api 网关契约） | `test/host-api.mjs`（fence 用例） |
| R8 | **误报控制**：未在配置中的 skill 不产生任何候选，未配置时目录与原样一致 | provider `list()` 仅对被禁用的名字返回占位 | `test/host-provider.mjs` |

## 2. 用户明确强调过的点

- **纯官方依赖**（issue #22 精神）：client 面板挂在官方 `slots` 扩展点（`settings.plugins.tab`），不依赖 dsh-better-sidebar；server 端只用官方 `ctx.skills` / `webServer` / `webRuntime` 服务。
- **宁可漏报也不误报**（继承文件活动插件原则）：禁用名单只含用户显式配置的名字。
