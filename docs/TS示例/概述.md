# TS 示例插件（dsh-ts-example）

> 源码: `plugins/dsh-ts-example/`（issue #47：新插件用 TypeScript 开发）

## 概述

`dsh-ts-example` 是仓库的 **TypeScript 插件开发示例**：演示新插件用 TS 开发的全流程——server 端 TS 源码 + `tsc` 编译（`lib/index.js` 产物）、client 端 TS 源码 + 构建时编译（`__ModuleLoader__` bundle）、CI 强制 `tsc --noEmit` 类型检查。**新 TS 插件照抄本插件结构即可**。

功能（演示用）：`GET /ts-example/api/greeting?name=xxx` 问候语路由（支持 `zh`/`en`）、`GET /ts-example/api/stats` 会话计数（监听 `session/start`）、侧边栏「TS 示例」页签（client TS → server TS 全链路）。

## TypeScript 开发说明

### 目录结构（TS 插件）

```
plugins/<name>/
├── src/
│   ├── index.ts              # server 端入口（export { name, inject, apply }）
│   ├── <模块>.ts             # server 端逻辑（纯函数，可单测）
│   ├── types.d.ts            # DSH 运行时类型声明（ctx / webServer 最小契约）
│   └── client/
│       └── index.ts          # client 端入口（单文件，见下方约束）
├── lib/
│   ├── index.js              # tsc 编译产物（server，必须提交）
│   ├── client.src.js         # __ModuleLoader__ 模板（手写 JS）
│   └── client.js             # 构建产物（必须提交）
├── scripts/
│   └── build.mjs             # client 构建（tsc 编译 → 注入模板）
├── test/                     # vitest 单测 + 冒烟（import 编译产物）
├── tsconfig.json             # server 构建配置（nodenext → lib/）
├── tsconfig.client.json      # client 构建配置（commonjs → lib/.client-build/）
└── package.json
```

### Server 端（tsc 编译）

- 源码 `src/*.ts`，`tsc -p tsconfig.json` 编译为 `lib/*.js`（ESM，`module: nodenext`）；
- 相对 import 写 `.js` 扩展名（nodenext 要求，如 `import { x } from './greeting.js'`，tsc 自动映射到 `.ts` 源码）；
- 运行时类型（`ctx` / `webServer` / 请求响应）用 `src/types.d.ts` 手写最小契约（DSH 运行时模块由宿主提供，不装 cordis 类型包）；
- **产物必须提交**（CI 只跑 `node --check` + 测试，不跑构建）；改动 TS 源码后运行 `npm run build` 重新生成。

### Client 端（构建时编译）

- 源码 `src/client/index.ts`（**单文件**）：`tsc -p tsconfig.client.json` 编译为 CommonJS 单文件（`lib/.client-build/index.js`），`scripts/build.mjs` 注入 `lib/client.src.js` 模板的 `__CLIENT_BUNDLE__` 占位符，写出 `lib/client.js`；
- CommonJS 产物内联进 `__ModuleLoader__` factory 作用域后，`require` / `exports` / `module` 均为作用域变量（`require` 由加载器注入，`exports`/`module` 为模板局部变量），可直接运行；
- **约束**：client 端 TS 源码无运行时相对 import（内联后 `require` 只认识 DSH 运行时注入的模块，如 `react`）；类型声明可拆文件（`import type` 编译期擦除）；需要多文件/复杂打包时用 esbuild/tsdown（官方 `tsdown.client.ts` 协议）；
- 类型检查：`import { createElement } from 'react'` 等由根 `@types/react` 提供。

### 类型检查（CI 强制）

- 根 `tsconfig.json`（strict，`noEmit`）覆盖全仓 TS 源码，CI 跑 `npx tsc --noEmit`（本地 `npm run typecheck`）；
- 编译期发现：**模块不存在（TS2307）**、类型不匹配、未定义变量、拼写错误——#39 的 `require('dsh-md-render')` 类错误在 TS 下不可能发版出去；
- 分工：TS 源码的类型/模块检查由 tsc 负责；eslint 继续只检查 JS（typescript-eslint 尚不兼容 TS 7 原生编译器，见下方踩坑）。

## 踩坑记录

| 坑                                       | 现象                                                                                                      | 解决                                                                                                    |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| **TS 7 移除 `moduleResolution: node10`** | `TS5108: Option 'moduleResolution=node10' has been removed`                                               | client 构建用 `module: commonjs` + `moduleResolution: bundler`（TS 7 允许该组合）                       |
| **注释内 `/*` 提前闭合块注释**           | 注释里写 `/*__CLIENT_BUNDLE__*/` 等 → `TS1127 Invalid character` 一串解析错误                             | 注释里不写 `/*` 符号（占位符写作 `__CLIENT_BUNDLE__`）                                                  |
| **typescript-eslint 与 TS 7 不兼容**     | `typescript-eslint@8` peer 要求 `typescript <6.1.0`；TS 7 包不提供完整 JS API（`ts.createSourceFile` 等） | eslint 不检查 `.ts`（tsc strict 负责 TS 检查）；TS 产物（`lib/index.js` 等）加入 eslint/prettier ignore |
| **产物格式与 prettier 不一致**           | tsc 产物带分号/双引号，`prettier --check` 失败                                                            | 产物加入 `.prettierignore` + `eslint.config.js` ignores（下次构建即覆盖，格式化无意义）                 |
| **client 端相对 import 运行时崩溃**      | 多文件 TS 编译产物含 `require('./x')`，内联后加载器不识别                                                 | client 端 TS 源码单文件；多文件用 esbuild/tsdown 打包                                                   |

## 与 issue #50（TS 7 引入）的关系

本 issue（#47）落地时直接使用 **TypeScript 7.0.2**（原生编译器 tsgo，2026-07 发布）：根 `tsconfig.json` 按 TS 7 配置（strict）、CI 类型检查基于 TS 7——同时满足 #50 的期望（"#40 落地时直接用 TS 7"）。#50 剩余工作（如全仓 TS 迁移评估）另行跟踪。
