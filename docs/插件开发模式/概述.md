# dsh-plugin-dev-mode — 插件开发模式 agent preset

## 定位

向 DSH 提供「插件开发模式」（preset id：`plugin-dev`）——**唯一启用 Cordis 工具集**的 Agent 模式，专用于开发、调试和维护 DSH 插件与动态 Cordis 插件。

与 shipped「创造模式」（cordis）的关系：能力等价于「标准模式 + Cordis 工具集」，但**主动去掉了高 token 成本项**，让开发插件时的 prompt 开销更小；同时作为仓库内可版本化的插件资产，随仓库演进。

> 本模块不是运行时插件（不挂载到 profile），而是 Agent preset 配置资产：`plugins/dsh-plugin-dev-mode/` 是源，`scripts/install.mjs` 将其安装到 `$DSH_HOME/.agent-presets/plugin-dev/`。

## 包含内容

```
plugins/dsh-plugin-dev-mode/
├── agent.cordis.yml          ← preset 组合（核心）
├── preset.yml                ← 显示元数据（名称/描述）
├── skills/
│   ├── editing-cordis-compositions/   ← 组合编辑规范（随 preset 安装）
│   └── cordis-plugin-development/     ← 动态插件开发规范（随 preset 安装）
├── scripts/install.mjs       ← 一键安装到 ~/.dsh/.agent-presets/plugin-dev/
├── README.md / CHANGELOG.md / LICENSE / package.json
```

### agent.cordis.yml 工具组合

| 组 | 行 | 说明 |
|---|---|---|
| 身份 | persona / agent-instructions | 精简 persona，声明本模式用途与技能加载要求 |
| shell | tool-bash / tool-pwsh | 平台自适应启用 |
| 文件系统 | tool-fs / tool-fs-search | read/write/edit/glob/grep |
| 后台任务 | tool-jobs | run_in_background 收集/停止 |
| goal | tool-goal | 长任务跨轮次目标 |
| compaction | compaction 组（isolate realm） | 长会话省 token 关键机制 |
| 技能 | skill-filesystem（customSkillDirs → 本 preset skills/）+ tool-skill | 随包技能 + 全局技能目录 |
| 交互 | tool-ask-user / tool-todo | 询问确认与任务清单 |
| **Cordis 工具集** | **tool-cordis** | **`cordis_inspect_*` / `cordis_define` / `cordis_run` / `cordis_stop` / `cordis_undefine`** |

### 与「创造模式」的差异（省 token 项）

| 删除项 | 成本 | 需要时 |
|---|---|---|
| plan mode（planning 组） | 约 110 行常驻 section | 切换标准模式 |
| 子代理/工作流（delegation 组：subagent/subagent_fork/workflow/ralph/subagent-control） | 6 个长描述工具 | 切换标准模式 |
| web 搜索（tool-web） | 长描述工具 | 切换标准模式 |

## 安装与使用

```sh
# 1) 安装 preset（在仓库内）
cd plugins/dsh-plugin-dev-mode && npm run install:preset
# 2) 重启 DSH 进程（preset 启动时读取）
# 3) Web GUI 模式选择器 → 切换到「插件开发模式」
```

建议将 `~/.dsh/settings.yaml` 默认模式设为标准模式，日常会话不带 Cordis 工具集：

```yaml
agent-presets:
  default: standard
```

## 注意事项（踩坑）

1. **与「创造模式」同进程互斥**：`dsh-tool-cordis` 的 inspect 注册表是**进程级单例**（`CordisInspectRegistryService.register` 对重复 provider id 抛错）。同一进程内只能有一个 preset 挂载 Cordis 工具集——不要同时开「创造模式」和「插件开发模式」会话，否则后挂载的会话失败。
2. **preset 改动需重启进程生效**：编辑 `agent.cordis.yml` 后，standing mount 已存在，需重启 DSH 进程。
3. **删除插件开发模式**：`rm -rf ~/.dsh/.agent-presets/plugin-dev` 后重启进程。

## 验证记录

- `agentPresets.standingKeyFor('plugin-dev')` 真实挂载验证通过（standard/cordis/plugin-dev 三 preset 对照，组合无 realm 冲突、无包缺失、无未激活行）。
- tool-cordis 的进程级单例限制为实测确认（首个挂载成功，第二个 preset 挂载报 `Host Cordis inspect provider "Service" is already registered`）。
