## 4. 关键技术约束与踩坑（务必先读）

### 4.1 ModuleLoader 机制（拆分 client.js 的前提！）

- `lib/client.js` 是 `window.__ModuleLoader__.load({ id, factory: (require) => { ... } })` 格式，内部 `require('react')`。
- **拆分 client.js 需要确认 DSH 浏览器端 ModuleLoader 是否支持相对路径 require（如 `require('./utils.js')`）**——其实现位于 DSH 浏览器构建产物（Node 侧不可见），无法静态确认。
- **必须先验证**（用 `verifying-dsh-plugins` skill 的流程：独立 DSH_HOME + 独立端口 + 真实浏览器）：
  1. 写一个最小实验：把 client.js 里一个纯函数（如 `formatRelative`）拆到 `lib/format.js`，client.js 里 `require('./format.js')`；
  2. 在验证实例里确认插件正常挂载、页签功能正常；
  3. 若不支持相对 require，备选方案：**不拆 client.js，改为在 factory 内用「子文件拼接」**（构建时拼接，类似 mermaid 的 build 流程）——即把大 factory 拆成多个"片段文件"，由 build 脚本拼回单一 client.js。此方案不改变运行时形态，但需要为相关插件引入 build 步骤。
- **client-render.mjs 测试的 require mock 也要同步支持相对路径**：目前 `registered.factory((spec) => { if (spec === 'react') return stubbed; throw })`，拆分后需处理 `./xxx` 的 require。

### 4.2 Stryker 不识别「脚本式测试」⚠️ 已踩过的坑

- 脚本式测试文件（断言写在模块顶层 + 末尾注册空 `test()`）**不被 Stryker 的 vitest-runner 识别**——变异永远不会被判定 killed。
- 所有 `host-smoke.mjs` 已改造为标准 `test()` 结构（改造效果：guardian 47.6%→73.2%、think-zh 0%→75%、dfa 71.8%→78.5%）。
- **新增/修改任何测试，断言必须写在 `test()` 内部**，禁止脚本式顶层断言。

### 4.3 Gherkin zh-CN 关键字

- **zh-CN 的 Given 关键字是「假如」**（不是「给定」！「给定」不被识别，步骤会静默 undefined）。
- 步骤定义函数参数个数必须与 cucumber 表达式参数匹配（`{string}` 一个参数 → 回调必须声明 1 个参数，否则报 "function has 0 arguments"）。
- `()` 在步骤文本中需转义为 `\(\)`（cucumber 表达式把括号当 optional 语法）。
- `/` 在步骤文本中需转义为 `\/`。

### 4.4 覆盖率统计范围（有意设计）

- v8 coverage **不统计 eval 加载的代码** → client.js（`__ModuleLoader__` 格式、测试用 eval 加载）不在覆盖率统计内。
- coverage `include: ['lib/index.js']`（只统计 server 端）；mermaid（client-only）在 `vitest.config.mjs` 中 `thresholds: {}` 豁免。
- **client 端质量由 client-render 断言 + Gherkin 场景 + 真实环境验证（门禁 10）覆盖**——拆分 client.js 后必须保持这三层覆盖，不能只靠单测。

### 4.5 变异测试范围

- Stryker `mutate: ['lib/index.js']`（server 端）；client.js 因 eval 加载不可变异。
- 配置已排除 StringLiteral/TemplateLiteral（label/文案类低价值变异）。
- **拆分 server 端后必须重跑 Stryker 确认分数仍 ≥70%**（变异测试是防"拆分改坏逻辑"的强保护）。

### 4.6 其他

- ESLint ignores 已包含 `**/.stryker-tmp/`、`**/reports/`、`**/coverage/`（Stryker/vitest 产物）——**不要提交这些目录**。
- 测试临时目录：各测试文件用 `mkdtempSync` 独立目录，`afterAll` 清理；guardian 测试需在 teardown 关闭 fs.watch（否则进程挂住）。

## 5. 拆分执行守则（防复发）

1. **拆分前**：跑该插件 `npm test` 全绿（121 单测 + 36 Gherkin 场景是行为锁定基线）。
2. **每拆一个模块**：立即跑该插件 `npm test` + `npx stryker run`（变异分数 ≥70% 是行为等价性证明）。
3. **client.js 拆分**：额外做真实环境验证（`verifying-dsh-plugins` skill：独立端口 3081 + 真实浏览器），确认挂载/页签/预览正常。
4. **拆完后**：全量 `npm test` + `npx eslint plugins/`（含尺寸规则）+ `npx depcruise plugins/` 全绿。
5. **提交**：按模块拆分粒度分批提交（如 `refactor(plugin): 拆分 dfa server 端 fence 子模块`）。
6. **更新差距文档**：G9-G12 状态 → ✅；G3 → ✅（CI 启用尺寸规则后）。
