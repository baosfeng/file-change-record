# 构建与测试

> ⚠️ **何时阅读：** 构建/测试/提交前必读。

## 测试执行与修复

### 测试执行要求

> **提交前必须运行全部测试，修复所有失败的测试用例，确保全部通过。**

- 每次提交前都应当运行项目对应的测试命令
- 如果存在测试失败，必须修复后才能提交
- CI（`.github/workflows/ci.yml`）会遍历 `plugins/*/` 执行 `node --check` 语法检查 + `npm test` 冒烟测试

## 常用测试命令

- 单个插件冒烟测试：`cd plugins/<插件名> && npm test`（即 `node test/host-smoke.mjs`）
- 语法检查：`node --check plugins/<插件名>/lib/index.js` 与 `lib/client.js`
- 遍历全部插件：`for d in plugins/*/; do [ -f "$d/package.json" ] && (cd "$d" && npm test); done`
- 依赖浏览器/真实 GUI 的测试（`test/e2e-cdp.mjs`、`test/client-render.mjs`）留本机手动运行

> **精简测试输出：** 冒烟测试为纯 Node 脚本，输出即摘要；无需额外静默参数。

## 单元测试与集成测试

### 单元测试（冒烟测试）
- 位于 `plugins/<name>/test/`（如 `host-smoke.mjs`，mock ctx / webServer / betterSidebar）
- **每次提交前必须自动运行并全部通过**
- 如果存在失败的测试，必须先修复后才能提交
- 运行命令：`cd plugins/<name> && npm test`

### 集成测试（手动）
- 涉及真实 DSH 进程/浏览器的测试（`e2e-cdp.mjs` 等）**必须人工指定触发**，不得随 CI 自动运行
- 由开发者在确认环境就绪后手动执行

## 测试设计

- 测试必须使用真实代码与 mock 的 ctx / webServer / betterSidebar，避免启动真实宿主
- 一个测试只测一个行为，测试名描述期望行为（见测试规范 skill）
- 覆盖边界情况：空 path、非法 sessionId、损坏状态文件、LRU 上限裁剪、重复访问去重

## 测试覆盖率检查

> **行覆盖率 ≥ 85%，分支覆盖率 ≥ 75%**（新增代码增量覆盖）。

- 覆盖率统计针对 `plugins/<name>/lib/`（server 端 `index.js` 为主）
- 无内置覆盖率工具时，用 `node --experimental-test-coverage`（Node 20+）或 `c8` 生成报告
- 每次新增代码必须添加测试用例，提交前检查覆盖率达标

## 异常处理原则

> **任何测试异常都必须被处理，不得遗留。**

### 与当前修改无关的异常
- 如果测试过程中出现异常，但经确认**与当前代码修改无关**：
  1. 当前可以**只关注自己的修改**，继续完成当前任务
  2. 但**必须记录该异常**（记录到 `docs/踩坑/` 或提交一个 Issue）
  3. **事后必须及时修复**，不得无限期搁置
  4. **修复后更新踩坑记录**：对应条目状态改为「已解决」，添加一句话解决参考（≤ 100 字）

### 必须修复的异常
- 与当前修改直接相关的测试失败 → **必须先修复才能提交**
- 新引入的语法错误或依赖冲突 → **必须先解决**

## 发布到仓库

- 只发布 **GitHub Release**（不发布 npm）
- tag 格式：`<包名>@v<版本>`（如 `dsh-file-activity@v0.4.0`）
- 发布流程详见 [快速上手](../概览/快速上手.md) 与 `.github/workflows/release.yml`：
  1. `package.json` 版本递增（semver）
  2. `CHANGELOG.md` 顶部加对应 `## [x.y.z]` 段落
  3. `git tag <包名>@v<版本> && git push origin <包名>@v<版本>`
  4. GitHub Actions 自动：校验插件目录与版本一致 → 跑测试 → `npm pack` 打 tarball → 创建 Release（附件 tarball + CHANGELOG 段落）

## 提交策略

代码修改完成后，**一次性提交**完整的代码 + 测试 + 文档变更，确保提交后的仓库处于可发布状态。提交信息遵循 [提交规范](../../.reasonix/skills/commit-standards/SKILL.md)。

## ✅ 操作前自查清单

- [ ] 单元测试已全部通过（强制要求）
- [ ] 集成测试已人工确认环境就绪后执行（如需）
- [ ] 与当前修改无关的测试异常已记录并承诺事后修复
- [ ] 我已按功能单次提交，提交信息符合提交规范
