# 版本号管理

> ⚠️ **何时阅读：** 改版本号/发版前必读。

## 版本号格式

各插件使用语义化版本 `主版本.次版本.修订号`（semver）。

## 变更级别与版本号对应

| 变更级别 | 版本号变更 | 触发场景                  |
| -------- | ---------- | ------------------------- |
| 小改动   | 修订号 +1  | Bug 修复、微小调整        |
| 中等改动 | 次版本 +1  | 新增功能、非破坏性变更    |
| 大改动   | 主版本 +1  | 破坏性 API 变更、架构重构 |

## 版本号管理操作流程

1. 运行全部测试并确认通过（`cd plugins/<名> && npm test`）
2. 更新 `plugins/<名>/package.json` 的 `version` 字段
3. 更新 `plugins/<名>/CHANGELOG.md` 顶部加对应 `## [x.y.z]` 段落（Keep a Changelog 格式）
4. 提交代码
5. 打 Git 标签：`git tag <包名>@v<版本> && git push origin <包名>@v<版本>`
6. 更新根 README 插件列表的版本号与简介

> 若代码内硬编码了版本常量，一并同步；tag 版本必须与 `package.json` 版本一致（workflow 强校验，不一致直接失败）。
