# 扩展开发

> ⚠️ **何时阅读：** 开发扩展（新插件）前必读。

## 扩展机制说明

本仓库是 DSH 插件集合仓库，**插件即是扩展**：每个插件是 `plugins/<name>/` 下的自包含 Cordis bundle，通过 `cordis.patch.yml` 挂载到 DSH 宿主，接入 `dsh-better-sidebar` 服务。插件可消费宿主服务（`webServer` / `sessions` / `webRuntime` / `betterSidebar`），注册页签、预览器、事件监听与 HTTP 路由。

## 如何开发扩展

完整流程见 [插件开发技能](../插件开发技能/概述.md)（源码 `skills/dsh-plugin-development/SKILL.md`），核心步骤：

1. **搭骨架**：在 `plugins/<新插件名>/` 创建自包含插件包（package.json + cordis.patch.yml + lib/ + README + CHANGELOG + LICENSE），可复制现有插件作参照。
2. **写 package.json**：包名 `dsh-<功能>`，`dsh.bundle.patch` 指向 cordis.patch.yml，peer 依赖声明 cordis / dsh-better-sidebar / react。
3. **写 Server 端** `lib/index.js`：`export const name / inject / apply(ctx)`；`ctx.on()` 监听事件；`ctx.webServer.register()` 注册路由（handler 先做 loopback 信任围栏）。
4. **写 Client 端** `lib/client.js`：`window.__ModuleLoader__.load` 格式；`ctx.effect(() => ctx.betterSidebar.registerTab(...))` 注册页签。
5. **写测试**：`test/` 下放纯 Node 冒烟测试（mock ctx / webServer / betterSidebar）。
6. **本地验证**：`dsh plugin --profile web add link:<路径>` → 硬刷新浏览器。
7. **发布**：版本号 + CHANGELOG → tag `<包名>@v<版本>` → GitHub Release。

## 已提供的扩展点

| 宿主能力              | 说明                             | 消费方式                                                             |
| --------------------- | -------------------------------- | -------------------------------------------------------------------- |
| better-sidebar 页签   | 在侧边栏注册新页面               | client 端 `ctx.betterSidebar.registerTab`                            |
| better-sidebar 预览器 | 注册文件预览渲染器               | client 端 `ctx.betterSidebar.registerFileViewer` / `matchFileViewer` |
| webServer 路由        | 插件 HTTP API                    | server 端 `ctx.webServer.register`                                   |
| DSH 事件              | 监听宿主事件（如 `fs/observed`） | server 端 `ctx.on`                                                   |
