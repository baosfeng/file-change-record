# dsh-notify 需求清单

> 维护规则：任何功能开发或修改必须对照本清单做回归检查；新增功能必须在本清单补充条目并添加测试覆盖。

## 回归检查（每次改动后）

- [ ] `npm test`（host 冒烟测试）通过
- [ ] 功能 1：对话回复完成后浏览器弹通知 + 滴声；点击跳转到该会话
- [ ] 功能 2：agent 调用 `ask_user_question` 时弹「询问」通知；回答后对话正常继续
- [ ] 功能 3：触发沙箱批准请求时弹「审批」通知；批准流程正常
- [ ] 功能 5/6：通知标题 = 会话标题；点击跳转正确
- [ ] 功能 8：`curl -X POST /notify/api/trigger`（本机）可触发通知；token 校验生效
- [ ] 功能 10：设置 → 插件 → 通知提醒 页签可见；修改开关保存后立即生效（如关闭 end 后不再弹结束通知）；重启后配置保持
- [ ] 无副作用：插件禁用/卸载后无残留样式、无残留 EventSource、无残留路由（`ctx.effect` 持有 disposer）

## 易碎点

- **瀑布事件不可干扰**：`tools/pre-execute` 与 `approval/request` 是 waterfall 事件，监听器必须调用 `next()` 使流程继续；漏掉 `next()` 会导致工具/审批流程挂死。
- **子代理过滤**：`agent/status` 对所有 agent（含 subagent）派发，判定必须白名单化——`session.header.origin === 'subagent'` / `header.delegationDepth > 0` / 运行时 `agent.options.subagentDepth > 0` 任一命中即子代理；header 缺失或结构不完整保守视为子代理，只通知明确无任何子代理标记的顶层会话。`subagentEnd: true` 后子代理完成也推送（标题带「子代理」前缀）。
- **SSE 长连接**：handler 不能 `response.end()`；客户端断开需监听 `close` 清理；需周期心跳防止空闲断连。
- **浏览器自动播放策略**：AudioContext 需用户首次交互后解锁（`resume`）；页面加载后可提前创建但保持 suspended，在首个 `pointerdown`/`keydown` 时恢复。
- **通知权限**：`Notification.requestPermission()` 应在用户可感知的时机（首次收到通知）发起，避免加载即弹权限弹窗。
