# 插件管理（dsh-my-plugin-manager）

> ⚠️ **何时阅读：** 想统一管理 DSH 插件（浏览市场、安装/卸载、检查更新）时，或修改本插件代码前。

## 功能一句话

**在 DSH 设置页统一维护插件生命周期：市场浏览/搜索（npm registry）→ 一键安装/卸载（`dsh plugin` CLI 同一数据源）→ 更新检查（pnpm outdated）→ 已安装清单（官方 pluginInventory）。** 插件独立于 DSH 主程序发版节奏，随时可更新。

## 解决的问题

DSH 插件的安装/更新/卸载此前依赖手动操作（`dsh plugin add` 命令行、手工编辑 `cordis.patch.yml`、靠 git pull 更新），插件一多管理成本明显上升（issue #2）。本插件把整套生命周期搬进 Web 设置页：

- **浏览与搜索**：npm registry 是公开插件的事实来源（`keywords:dsh` 全覆盖）；
- **安装/卸载**：复用 `dsh plugin --profile <p> add|remove`（pnpm），自动维护 profile package.json 与 bundle patch，不做手写编辑；
- **更新检查**：`pnpm outdated --json` 解析，展示 `当前 → 最新`，插件独立于 dsh 发版节奏；
- **已安装管理**：官方 `pluginInventory` 服务（loader 条目）+ profile `node_modules` 版本解析（含 scoped 包）；只列出用户安装的插件，官方/内置命名空间（`@deepseek-ai/*`、`cordis`/`cordis:*`、`@koishijs/*`）自动过滤（issue #28）。

## 工作机制

```
设置 → 插件 → 插件管理（官方 slots 扩展点，纯官方依赖）
        ↓ GET /my-plugin-manager/api/installed
ctx.pluginInventory.list()（loader 条目，过滤官方命名空间）+ profile node_modules 版本
        ↓ GET /my-plugin-manager/api/search?q=…
npm registry search API（keywords:dsh 全覆盖）
        ↓ POST /my-plugin-manager/api/install|uninstall
spawn `dsh plugin --profile <p> add|remove`（与 CLI 同一数据源）
        ↓ GET /my-plugin-manager/api/updates
spawn `dsh plugin --profile <p> outdated --json` → 解析 current/latest
```

## 业务场景映射

| 业务关键词                                             | 入口与方法（源码路径）                                                                                                                                     |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 安装/卸载/更新检查（CLI 封装）                         | `plugins/dsh-my-plugin-manager/lib/manage.js` — `runDsh()`（spawn + 输出收集）/ `installPlugin()` / `uninstallPlugin()` / `outdatedPlugins()`（JSON 解析） |
| 市场搜索（npm registry）                               | `plugins/dsh-my-plugin-manager/lib/registry.js` — `searchNpmPlugins()` / `latestVersionOf()`（含字段防御式归一化）                                         |
| API 路由（installed/search/install/uninstall/updates） | `plugins/dsh-my-plugin-manager/lib/api-route.js` — 方法→handler 映射表 + fence + 参数校验                                                                  |
| profile 解析                                           | `plugins/dsh-my-plugin-manager/lib/index.js` — `currentProfile()`（`--profile` 参数优先，默认 web）/ `profileDirOf()`（$DSH_HOME/profiles）                |
| 设置页面板                                             | `plugins/dsh-my-plugin-manager/lib/client.js`（client）— `ctx.slots.inject('settings.plugins.tab', …)`，已安装/市场两区块                                  |

## 安装与使用

1. 安装插件：

   ```bash
   dsh plugin --profile web add dsh-my-plugin-manager --trust-lockfile
   ```

2. 打开 DSH Web 设置 → 插件 → **插件管理**；
3. **已安装**：查看清单（名称 / 版本 / 状态）、逐行「卸载」、「检查更新」显示 `旧 → 新`；
4. **市场**：输入关键词搜索 npm 插件，点「安装」写入 profile；
5. 安装/卸载落盘即时生效，新插件下次重启 DSH 后加载（候选区热挂载由 dsh-my-guardian 负责）。

## 边界与限制

- 安装/卸载/更新检查走 `dsh plugin` CLI（spawn），需 PATH 中存在 `dsh` 命令（正常 DSH 环境满足）；
- profile 名默认 `web`（`--profile` 参数优先），多 profile 场景请用带参数的启动方式；
- 新插件加载需要重启（本插件不做运行时热挂载——那是 dsh-my-guardian 的职责）；
- 面板为可选增强：`ctx.get('slots')` 缺省时静默跳过注册，server 端 API 不受影响。
