# 快速上手

## 1. 安装插件到 DSH

前置：已安装 `dsh-better-sidebar`（v0.12+，推荐 v0.14）。

```sh
# 推荐：dsh plugin 安装（link 指向本仓库插件目录）
dsh plugin --profile web add link:/Users/bsfeng/IdeaProjects/my-dsh-plugins/plugins/dsh-file-activity
```

装完后**硬刷新浏览器**（Cmd/Ctrl+Shift+R）。

> 编辑 profile 的 `cordis.patch.yml` 会在运行中通过 Cordis HMR 热挂载 server 端，无需重启 `dsh web`；client 端在页面刷新后生效。
> 更多安装方式（手动依赖 + patch）见 [安装与导入](../快速集成/安装与导入.md)。

## 2. 使用文件活动页签

1. 侧边栏 `+` 菜单 → **文件活动**（会话首次自动打开）。
2. **最近访问**：LRU 记录（每会话最多 5 条），点击文件弹出浮窗预览（复用侧边栏内置渲染：代码高亮 / Markdown / 图片 / PDF / HTML）。
3. **文件统计**：读取/新增/修改次数按绝对路径组织成树形目录，文件夹可折叠。
4. 顶部图标：刷新（重载）、清空（删除当前会话全部记录）。

## 3. 开发新插件

1. 先读 [插件开发技能](../插件开发技能/概述.md)（或 `skills/dsh-plugin-development/SKILL.md`）。
2. 在 `plugins/<新插件名>/` 创建自包含插件包（package.json + cordis.patch.yml + lib/ + README + CHANGELOG + LICENSE）。
3. 本地验证：`dsh plugin --profile web add link:<绝对路径>/plugins/<新插件名>`。
4. 更新根 README 插件列表与 `plugins/<新插件名>/README.md`。

## 4. 发布插件（GitHub Release only）

> 完整发布流程（实测验证 2026-08-23，含失败排查）见 [插件开发技能 - 发布](../插件开发技能/概述.md) 与 [踩坑：release 校验失败](../踩坑/github-release版本校验失败.md)。

```sh
# 1) 确认就绪：package.json 版本递增（semver）+ CHANGELOG 加段落 + 根 README 插件列表版本号同步 + 全部测试通过
# 2) 先推送 main（tag 需指向已推送的提交，含 workflow 与版本改动）
git push origin main
# 3) 打 tag 并推送（触发 GitHub Actions Release workflow）
git tag <包名>@v<版本> && git push origin <包名>@v<版本>
# 4) workflow 自动：解析 tag → 校验插件目录 → 冒烟测试 → 校验版本一致 → npm pack → 提取 CHANGELOG 段落 → 创建 Release
# 5) 验证：GitHub Releases 页面或 API 确认 Release + tarball 附件已生成
```

> tag 版本必须与 `package.json` 版本一致（workflow 强校验，比较的是**不带 v** 的裸版本号）；发布失败时先看 Actions 日志定位失败步骤（2026-08-23 曾遇 workflow 校验 bug，已修复）。
