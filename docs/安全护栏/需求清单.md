## 易碎点

- **waterfall 透传**：`tools/pre-execute` 监听器必须先 `await next()` 拿到下游决策再决定是否覆盖；observe 模式一律原样返回下游决策。绝不吞掉 next()（会导致工具流程挂死）。
- **只读观察契约**：默认 observe 模式不改变工具/审批流程（参考 dsh-my-notify）；ask/deny 是用户显式开启的可选模式，走 DSH 原生 gate 机制。
- **投毒扫描不阻塞**：`dsh plugin add` 联动扫描是 fire-and-forget（void promise），绝不阻塞 waterfall；扫描只读包内容，绝不执行包内脚本/代码。
- **持久化竞态**：store 异步加载期间的事件必须缓冲；卸载（dispose）时未就绪缓冲要回放；加载完成时不能覆盖本进程已产生的告警（mergeCurrent）。
- **注入检测误报控制**：过滤 `source.kind === 'plugin'` 的插件注入消息（runtime-context 快照等非用户输入），避免误报。
- **扫描膨胀**：文件数（2000）/单文件大小（512KB）上限；跳过 node_modules/.git/coverage 等目录。
