# dsh-md-render 需求清单

> ⚠️ **每次开发本插件的新功能或修复前，必须逐条对照本清单**：新改动不得破坏任何一条既有需求；涉及「表格检测 / 流式兼容 / 思考模式回归」的需求变更后必须跑回归验证（见 [构建与测试](../开发指南/构建与测试.md#需求回归)）。

## 需求条目

| # | 需求 | 说明 | 验收标准 | 测试覆盖 |
|---|------|------|---------|---------|
| R1 | **非思考模式标准 GFM 表格渲染为表格** | 非思考模式（text 块）下，模型输出的标准 GFM 表格（首尾管道符 + 分隔行）渲染为表格（表头/边框/对齐） | 标准表格以 `<table>` 渲染，含 thead/tbody、逐列对齐 | `test/table-detect.mjs`（标准 GFM 解析）；`test/client-render.mjs`（渲染断言）；真实环境验证（浏览器 DOM 断言） |
| R2 | **无首尾管道符的表格也能识别渲染** | 表头/数据行只需含 `\|` 且 ≥2 列（允许无首尾管道符），分隔行支持 `--- \| ---`、`-\|-\|-`、`---` 等变体 | 不标准表格（无首尾管道符）渲染为表格，不再以纯文本段落展示 | `test/table-detect.mjs`（无首尾管道符 + 分隔行变体）；`test/client-render.mjs`（段落替换断言）；Gherkin 场景；真实环境验证 |
| R3 | **对齐标记生效** | `:---` 左对齐、`:---:` 居中、`---:` 右对齐，逐列生效 | 对齐标记解析正确，th/td 的 textAlign 正确 | `test/table-detect.mjs`（对齐解析）；`test/client-render.mjs`（对齐 style 断言）；真实环境验证 |
| R4 | **宽表格横向滚动/溢出处理** | 表格外层 `div.dmr-table-scroll` 容器 `overflow-x: auto`，宽表格不撑破消息气泡 | 宽表格可横向滚动，容器 max-width 100% | `test/client-render.mjs`（滚动容器断言）；真实环境验证（计算样式断言） |
| R5 | **表格样式（表头/边框）** | 表头底色 + 加粗、行分隔线，走 DSH 语义 token，深浅主题自适应 | 样式随 activation 注入、fiber teardown 卸载；表头/边框样式生效 | `test/client-render.mjs`（样式注入断言）；Gherkin 场景；真实环境验证（截图） |
| R6 | **兼容 dsh-think-zh-expand** | 识别其 MarkdownView 产出的 `div.tzx-md` 容器；已渲染的表格（`table.tzx-table`）不重复处理 | 两个插件同时启用时表格正常渲染；已渲染表格保持原样 | `test/client-render.mjs`（已渲染表格跳过断言）；Gherkin 场景；真实环境验证 |
| R7 | **兼容内置 MarkdownText** | 识别内置渲染器的 `div.md-table-wide` 宽表格容器，不干扰已渲染表格 | 内置渲染的表格保持原样 | `test/client-render.mjs`（md-table-wide 容器断言）；真实环境验证 |
| R8 | **流式兼容** | MutationObserver 跟随消息流式渲染；流式中的容器（`[data-streaming]` 祖先）等内容稳定后再处理 | 流式生成中出现的表格最终渲染为表格；流式中的容器不提前处理 | `test/client-render.mjs`（流式跳过断言）；真实环境验证 |
| R9 | **思考模式（reasoning 块）表格渲染不受影响** | 思考块内已渲染的表格（`table.tzx-table`）不被重复处理或破坏 | 思考块内表格保持原样 | `test/table-detect.mjs`（思考模式同款输入回归）；Gherkin 场景；真实环境验证 |
| R10 | **零运行时依赖** | 表格检测与渲染全部自实现，不引第三方库 | package.json 无新增运行时依赖 | 依赖结构检查（depcruise） |

> **配置说明**：本插件**无应用层配置项**（`apply(ctx)` 不接收 config 参数），设置页无可视化配置入口，插件激活即生效（README「配置」节注明"无配置项"）。

## 回归检查（每次改动后）

- [ ] `npm test`（表格检测单测 + client 渲染路径 + Gherkin 验收）通过
- [ ] 构建产物 `lib/client.js` 语法检查通过（`node --check`）
- [ ] 与 dsh-think-zh-expand 共存时表格正常渲染（手动/真实环境）
- [ ] 思考模式（reasoning 块）表格渲染不受影响（回归）
- [ ] 无副作用：插件禁用/卸载后无残留样式、无残留表格

## 易碎点

- **构建产物**：`lib/client.js` 是构建产物（parts 拼接），修改 `client.src.js` 或 `lib/parts/` 后必须 `npm run build` 并提交产物；CI 不执行构建。
- **检测规则**：表格检测规则（`isTableLine` / `isSeparatorLine` / `parseTable`）是核心逻辑，改动必须同步更新 `test/table-detect.mjs` 并保持全绿。
