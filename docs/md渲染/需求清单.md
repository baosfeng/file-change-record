## 回归检查（每次改动后）

- [ ] `npm test`（表格检测单测 + client 渲染路径 + MarkdownView 单测 + Gherkin 验收）通过
- [ ] 构建产物 `lib/client.js` 语法检查通过（`node --check`）
- [ ] 与 dsh-think-zh-expand 共存时表格正常渲染（手动/真实环境）；think-zh-expand `npm test` 全绿（双 bundle 加载）
- [ ] 思考模式（reasoning 块）表格渲染不受影响（回归）
- [ ] mermaid 代码块容器（`div.md-code-block`）结构保持，dsh-mermaid-render `npm test` 全绿（无改动）
- [ ] 无副作用：插件禁用/卸载后无残留样式、无残留表格

## 易碎点

- **构建产物**：`lib/client.js` 是构建产物（parts 拼接），修改 `client.src.js` 或 `lib/parts/` 后必须 `npm run build` 并提交产物；CI 不执行构建。
- **检测规则**：表格检测规则（`isTableLine` / `isSeparatorLine` / `parseTable`）是核心逻辑，改动必须同步更新 `test/table-detect.mjs` 并保持全绿。
- **输出结构兼容（issue #31）**：MarkdownView 输出类名（`div.tzx-md` / `p.tzx-p` / `table.tzx-table` / `div.md-code-block`）是跨插件契约——dsh-md-render 的 scanner 扫描 `p.tzx-p`、dsh-mermaid-render 扫描 `div.md-code-block`、think-zh-expand 的测试断言这些结构；改动类名必须同步更新三个插件的测试。
- **跨插件导出**：`exports.MarkdownView` 是 think-zh-expand 的跨 bundle require 契约（`dsh.client.external`），删除/改名会破坏 think-zh-expand 的 client 端 materialize。
