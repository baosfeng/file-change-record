# dsh-task-reliability 需求清单

> 维护规则：任何功能开发或修改必须对照本清单做回归检查；新增功能必须在本清单补充条目并添加测试覆盖。
>
> 插件定位：保证 DSH 中的任务可靠执行完成 —— 模型超时/请求失败自动重试、任务未完成自动继续、思考重复检测干预、系统休眠后重启恢复、独立完成度校验 agent、自主决策模式（出行防中断）、远程触发接口。

## 易碎点

- **瀑布事件不可误伤**：`agent/request-error` 与 `tools/pre-execute` 是 waterfall；不接管时必须调用 `next()`；接管（retry/deny）时**不要**调用 next()，否则双重处理。
- **turn-stopping 防死循环**：steer 会让机器再跑一步；必须内置护栏（同内容哈希去重 + 每任务循环上限 + 全局速率限制 + `signal.aborted` 检查），否则插件 bug 会造成 agent 无限循环。
- **校验 agent 生命周期**：创建后必须持有 `AgentHandle` 并在插件卸载/校验完成时 `dispose()`；校验 agent 的会话是独立持久化的，必须清理，否则残留脏数据。
- **校验 agent 不得干扰主流程**：校验在会话完全结束后异步进行；校验期间主 agent 保持 idle；唤醒用 `followup`（新 turn）而非 steer（避免与主 agent 自己排队的 next-step 混在一起）。
- **重启恢复幂等**：resume 前检查 `resumeAt`；同一任务只恢复一次；resume 失败（会话缺失）必须跳过并标记，不能阻塞插件启动。
- **持久化原子性**：`$DSH_HOME/task-reliability.json` 用 tmp+rename 原子写；防抖合并高频更新；损坏文件回退空表。
- **思考重复检测开销**：只保留最近 N 段 reasoning 文本用于相似度计算，不得累积全量；检测逻辑不得阻塞流（chunk 透传优先）。
- **远程接口安全**：trigger 路由必须 loopback 信任围栏；配置 apiToken 后要求 token 头；错误 token 一律 403。
