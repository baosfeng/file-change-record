# dsh-task-reliability — 任务可靠性保障

## 定位

保证 DSH 中的任务可靠执行完成。覆盖用户长任务执行中的六类中断场景：

1. **模型超时/请求失败**：模型调用超时或瞬态网络错误导致回合失败 → 请求级自动重试（不产生用户可见消息）。
2. **任务提前结束**：回合正常结束但任务未完成 → `agent/turn-stopping` 注入继续指令；校验模式下用独立 agent 判断完成度后决定是否继续。
3. **思考重复输出**：模型 reasoning 陷入重复循环 → 流级相似度检测 + 终止回合 + 分级打断指令。
4. **系统休眠/重启**：任务执行中进程中断 → 持久化任务注册表 + 启动时自动恢复（`agents.resume` + 继续指令）。
5. **锁屏/休眠唤醒后停滞**：系统挂起（macOS App Nap / 系统休眠 / 网络断开）导致任务停止，DSH 进程仍在运行 → 任务停滞看门狗定期扫描唤醒（无需重启 DSH）。
6. **ask 长时间无响应**：用户出远门后 agent 一直等待 `ask_user_question` → ask 超时自动继续（模拟回答 + 继续指令，问题记录待确认）。

配套能力：**自主决策模式**（出行防 ask 中断，问题收集待确认）、**远程触发接口**（手机/其他设备远程控制）。

## 架构

```
DSH 进程（Server 端 lib/index.js）
├── 任务注册表（持久化 $DSH_HOME/task-reliability.json，原子写 + 防抖）
│   └── 任务 { id, sessionId, description, status, mode(direct|verify), loopCount, verifyCount, resumeAt, … }
├── agent/request-error 监听 → 超时/瞬态失败重试（指数退避 + 上限）
├── agent/turn-stopping 监听 → direct 模式注入 steer 继续（防死循环护栏）
├── agent/status(idle) 监听 → verify 模式触发完成度校验流程
│   └── runVerification：创建独立校验 agent（verify-<taskId>）→ 读主会话日志 →
│       判断完成度 → 未完成 followup 唤醒主 agent（带结论）
├── llm/stream 包装 → reasoning 段落 n-gram 相似度检测 → 循环抛错 + 打断
├── tools/pre-execute 拦截（自主决策模式）→ ask_user_question → deny + 问题收集
├── tools/execute 包装（ask 超时）→ ask_user_question 空闲计时器（Promise.race）→
│   超时：记录待确认问题 + followup 继续指令 + 模拟回答（推荐选项/空回答）
├── approval.setPolicy（自主决策模式）→ 'never' 自动批准
├── 启动恢复扫描 → agents.resume + 继续指令（resumeAt 幂等）
├── 任务停滞看门狗（setInterval）→ 扫描活动任务 updatedAt 停滞 → 唤醒（live/resume + followup）
└── HTTP API /task-reliability/api/*
    ├── GET  info / tasks / questions / config
    ├── POST tasks / tasks/<id>/done|pause|resume|delete
    ├── POST questions/<id>/answer
    ├── POST mode（模式开关，可带 sessionId 会话级 autopilot）
    ├── POST trigger（远程触发：register/mode/answer/status）
    └── PUT  config（设置页保存配置）

浏览器（Client 端 lib/client.js）
└── 侧边栏页签 dsh-task-reliability:panel（模式开关 / 任务列表 / 待确认问题 / 注册表单）
    + 设置页 tab（14 项配置可视化）
```

## 关键设计决策

| 决策 | 理由 |
|------|------|
| 一个插件承载全部能力 | 共享任务注册表与模式状态；拆分为两个插件会导致状态同步问题 |
| 校验时机 = 会话完全结束后 | 用户选择；校验在 agent 空闲后异步进行，不打断主流程执行 |
| 校验 agent 独立创建 | 独立 sessionId / 独立 scoped world / 独立生命周期（dispose 清理），不注入主 agent 状态，不影响其他 agent |
| turn-stopping 注入 steer | DSH 原生机制：steer 后机器 re-reads inbox，fresh steering 再跑一步；无 steer 则关闭回合 |
| 请求级重试（request-error） | 与 dsh-client-auto-continue 的「错误后发『继续』用户消息」互补：请求级重试不产生用户消息、不消耗用户视角回合 |
| 思考重复用「终止回合 + 打断」 | DSH 无现成 reasoning 循环检测；流内无法安全中断，用抛错终止回合 + 下一回合带打断指令 |
| 护栏（loopCount / 冷却 / 速率限制） | steer 会让机器多跑一步，插件必须自带防死循环；否则插件 bug 会造成 agent 无限循环 |
| 持久化 resumeAt 幂等 | 重启恢复只执行一次；resume 失败（会话缺失）标记 failed 不阻塞启动 |
| ask 超时用 `tools/execute` 包装 + Promise.race | ask 挂起时 steer/followup 无法生效（turn 未结束），必须让 ask 工具"返回"：超时后返回模拟回答（推荐选项/空回答）解锁 turn，同时 followup 注入继续指令兜底；用户回答时 next() 先 resolve，真实结果透传 |
| 看门狗轮询替代系统电源事件监听 | Node 无内置电源事件 API；`system-sleep` 等 npm 包引入运行时依赖（违反无新增依赖约束）。看门狗轮询（默认 5 分钟间隔）在唤醒后最多一个周期内恢复任务，取舍可接受 |
| 看门狗唤醒温和失败 | 唤醒失败（会话暂时不可用）不标记 failed，留给下次轮询重试；唤醒后刷新 `updatedAt` 避免每个周期重复唤醒 |

## 与相关插件的关系

- **dsh-client-auto-continue**（用户已装）：网络错误后自动发送「继续」用户消息。本插件与其互补：请求级重试（底层）、完成度判断（校验 agent）、思考重复干预、休眠恢复、自主决策、ask 超时、停滞看门狗。两者可共存。
- **dsh-notify**：只读观察（ask/审批/结束通知）。本插件在自主决策模式下**主动拦截** ask（deny 且不调 next()），在 ask 超时后**模拟回答**—— 这是有意的行为差异。

## 验证

- 独立端口验证实例：`verifying-dsh-plugins` skill（3082 端口 + 独立 DSH_HOME）
- 真实环境场景：注册任务 → 模拟超时/提前结束 → 自动继续；开启校验 → 会话结束 → 校验 agent → 未完成唤醒；开启自主决策 → ask 被拦截并记录 → 远程回答；ask 长时间无响应 → 超时自动继续；任务停滞（锁屏/休眠）→ 看门狗唤醒
